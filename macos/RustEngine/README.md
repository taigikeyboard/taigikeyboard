# Rust shared-core artefacts (macOS)

`RustTaigi.xcframework`, `RustTaigi.swift`, and `SwiftBridgeCore.swift` are
regenerated by `engine/scripts/build-macos-xcframework.sh` (`make macos-engine`).

Do not edit those three manually. The committed copies exist so the SwiftPM
package resolves a stable `binaryTarget` path across a fresh clone.

`SwiftLoggerSink.swift` is the exception: it is **hand-written**. The generated
`RustTaigi.swift` declares `@_cdecl` shims that reference `SwiftLoggerSink` by
bare name, so the type has to compile in the same module — which is why it lives
here rather than with the rest of the app code. The build script only replaces
the three generated files, so it is safe alongside them.

`Package.swift` compiles this directory as the `RustTaigiSwift` target (the
`RustTaigi` module name belongs to the `binaryTarget`) in Swift 5 language mode,
because generated sources cannot be annotated for Swift 6 strict concurrency.

Single slice: `macos-arm64` (`aarch64-apple-darwin`). Intel is a user-gated
later step.

The xcframework wraps `engine/swift-ffi` (Rust) — the same crate iOS links.
Exported surface is the `mod ffi` bridge block in `engine/swift-ffi/src/lib.rs`;
not restated here, so the two platform READMEs cannot drift from it.

**Drift rule**: `engine/swift-ffi` is shared. After any change to that crate,
regenerate BOTH `ios/RustEngine/` (`make build`) and this directory
(`make macos-engine`).
