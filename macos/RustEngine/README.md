# Rust shared-core artefacts (macOS)

`RustTaigi.xcframework`, `RustTaigi.swift` and `SwiftBridgeCore.swift` are
generated by `engine/scripts/build-macos-xcframework.sh`, which `make build`
runs as its last step (`make macos-libs` runs it alone). They are gitignored;
the paths are stable so the SwiftPM package resolves its `binaryTarget` at a
fixed location. Do not edit them.

`SwiftLoggerSink.swift` is the exception: it is **hand-written**. The generated
`RustTaigi.swift` declares `@_cdecl` shims that reference `SwiftLoggerSink` by
bare name, so the type has to compile in the same module — which is why it lives
here rather than with the rest of the app code. The build script only replaces
the generated files, so it is safe alongside them.

`Package.swift` compiles this directory as the `RustTaigiSwift` target (the
`RustTaigi` module name belongs to the `binaryTarget`) in Swift 5 language mode,
because generated sources cannot be annotated for Swift 6 strict concurrency.

Single universal slice: `macos-arm64_x86_64` (`aarch64-apple-darwin` +
`x86_64-apple-darwin`, `lipo`'d into one archive).

The archive is `macos/crates/taigi-macos-ffi`: the desktop shell seam and
logger sink (`mod ffi` in `macos/crates/taigi-macos-ffi/src/lib.rs`,
wrapper `RustTaigi.swift`) over `taigi-desktop-core` and `dispatch`. The
surfaces are not restated here, so this README cannot drift from them.

**Drift rule**: after a change in `desktop/`, `macos/crates/` or `macos/Cargo.*`,
rebuild with `make macos-libs` before building or testing macOS. After an
`engine/` change, run `make build` so macOS, iOS and Android regenerate
together.
