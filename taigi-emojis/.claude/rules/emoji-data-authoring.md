# Emoji Data Authoring

Read before editing `src/overrides.tsv` or anything in `data/`.

## The overlay is the only hand-edited surface

`src/overrides.tsv` is where you add/curate emoji. Upstream `data/` is generated by
`make fetch` — never hand-edit it. Columns (tab-separated, trailing optional):

```
emoji  action  category  order  taigi_keywords  zh_Hant_keywords  en_keywords  name  notes
```

- `patch` — add keywords to an emoji already in upstream. Build fails if it is not.
- `add` — add a brand-new emoji not in upstream (needs `category` + `name`; `version` is
  recorded as `custom`). Use sparingly — prefer upstream.
- `exclude` — drop an upstream emoji.
- Keywords are `|`-separated (terms may contain commas).

After editing: `make build` then `make test`. The drift-guard test fails if committed
`dist/emoji.json` is stale.

## Taigi keywords — authoritative-source-only

Taiwanese romanization is **never invented**. This mirrors the parent repository's Core
Principle #3.

- For `taigi_keywords`, prefer 漢字 (unambiguous) and only add 羅馬字 (canonical TL) you have
  verified against `knowledge/taigi-phonetics-reference.md` and the root-level
  `taigi-converter` submodule.
- Do NOT guess tone marks or spelling. Leave 羅馬字 out rather than ship a wrong reading.
- A Taiwanese word's identity is the **(漢字, 羅馬字) pair** — same Hanji, different reading =
  different morpheme. Keep both readings when both are meaningful search terms.

## Versioning

`MAX_EMOJI_VERSION` (in `scripts/generate.py`) and the `Makefile` `CLDR_TAG` are pinned
together and documented in `data/SOURCES.md`. Raising the pin is a deliberate change:
`make fetch` → bump both → `make build` → review diff. Release scope/timing is user-gated.
