# Web Project Guidelines

Rules for the web version (`web/`: the `taigi-web` crate compiled to `wasm32-unknown-unknown`, over `desktop/` + the shared engine). Design record and phase plan: `docs/architecture/web-roadmap.md`.

## Build

- Run `cargo` from `web/` (`make -C web …`). Rustup reads `web/rust-toolchain.toml` from the working directory, and that file is what supplies the target.
- `make web-check` is the gate: release build, `wasm-bindgen`, `wasm-opt`, Node smoke test, clippy, biome, fmt. It builds from source, so it has no stale-artifact step. `make web-e2e` is the browser gate, separate because it downloads three browsers; on CI it runs Chromium only. `make web-serve` runs the page on `http://127.0.0.1:8000`.
- `make -C web site` stages `web/src/`, the bindings, the dictionaries, the fonts and the icons (the iOS app icon's 180, 196 and 512) into `web/target/site/`, the tree the browser sees. `scripts/stage-assets.mjs` runs last: it gzips the dictionaries under content-hashed names, writes `generated/dictionaries.js` and `assets-manifest.json`, and stamps `sw.js` with the build. `scripts/subset-fonts.sh` cuts the fonts to `web/target/fonts/`, and reruns only when a font or `fonts.css` changes. It needs `pyftsubset` (`mise install`). The output is 19 MB, so it is never committed.
- Deploy: `docs/architecture/web-release.md`. Every path in a page is relative, because the site lives under `/web/` and tests serve it from the root.
- `wasm-bindgen` is pinned twice, exactly: the crate in `web/Cargo.toml`, the CLI in `mise.toml`. Move both in one change; `make -C web bindgen-version` compares them. `biome.json`'s `$schema` follows the `biome` pin.
- SQLite's C is archived for this target with `zig ar` (`AR_wasm32_unknown_unknown` in `web/Makefile`): Apple's `ar` cannot index wasm objects, and the link then misses every `sqlite3_*`. Any workflow that builds the page installs zig from `mise.toml`.
- The release profile keeps `strip` off. `strip = true` removes the `target_features` section that `wasm-bindgen` and `wasm-opt` read; `wasm-opt` drops the debug names instead. `wasm-opt --all-features` emits an encoding Node 26 rejects (`unknown import kind 0x7f`).

## Rust

- No `#[cfg(target_family = "wasm")]` outside `engine/mmap-host`, `engine/lexicon/src/paths.rs`, `engine/userdata` (`database.rs`: no thread, so each send drains the store's queue on the caller's thread, and no directory or pre-takeover copy; `timestamp.rs`: the browser's clock; `handle.rs`: rooted paths) and the `mod bindings` line of `taigi-web`'s `lib.rs`. A difference the browser needs is a value the shell passes in (`RuntimeParts`), as the clock is.
- `bindings.rs` is the only module that names the browser: `wasm-bindgen` imports and `JsError` panic off this target, and `mmap_host::register` exists only on it. Everything else in `taigi-web` is plain Rust with native tests (`make -C web test`).
- No hand-written `unsafe`. `unsafe_code = "forbid"` holds with `#[wasm_bindgen]`.
- Anything on the key path that calls `SystemTime::now`, `Instant::now`, `std::fs` or `std::thread` compiles here and fails at run time. `cargo check` for this target proves nothing about those; the smoke test does.
- This target has no unwinding: a panic traps the instance (`rust-ffi-safety.md` §1.2).

## Page

- Dictionaries are gzip files read through `DecompressionStream`, so the result does not depend on what a host compresses. `loader.js` takes them one at a time, from Cache Storage or the network, through one SHA-256 check; only checked bytes are stored, and a damaged entry is dropped so that retry downloads it. Network reads use `cache: "reload"`: bad bytes may be what the HTTP cache holds.
- The page's dictionary list is `generated/dictionaries.js`, a module loaded with the page, so that an older page in the HTTP cache never meets a newer list. Only `sw.js` reads `assets-manifest.json`.
- `sw.js` is registered after the dictionaries are in, so a first visit fetches them once. Its install is all or nothing, and checks each file with `integrity`. It has no `skipWaiting` and no `clients.claim()`: a page's controller never changes, because trap recovery imports a new copy of the glue, which must match the wasm that page compiled. So a new version starts once every tab of the old one has closed; a reload does not do it, and neither does anything on screen. The exception is the tab of a first visit, which no worker controls: a deploy can activate past it, and a trap in that tab then pairs new glue with its old wasm and fails until a reload. The text stays readable. To see a rebuild in `make web-serve`, close the tab or use DevTools' "Update on reload".
- Cache Storage is per origin and `taigikeyboard.tw` also hosts other sites, so `sw.js` deletes only `taigi-web-*`.
- The CSP is a `<meta>`, the first thing in `<head>`, because Pages cannot set headers. Nothing inline and no `data:` URLs (the select's chevron is `chevron.svg`), except `style-src-attr 'unsafe-inline'`: WebKit's `<select>` sets a `style` attribute inside its shadow tree, and blocking it loses the ellipsis on a long option.
- The text is a Lexical editor (`editor.js`, maintainer 2026-11-10: formatting shows as in ZenPen and Calmly Writer, markers never), its root `#text`, bundled from the pinned npm packages into `vendor/lexical.js` by `make site` (`web/vendor/lexical.js` lists what the page imports; esbuild, because the page has no bundler and an import map would be an inline script the CSP forbids; Lexical's MIT licence ships beside it). Native `contenteditable` with `execCommand` was tried first and dropped: in Chromium and WebKit `formatBlock` / `insertUnorderedList` nest `<h2><ul>`, `insertHTML` rewrites the next block, and undo steps differ per engine. One write path for the engine: `surface.js` over `Editor`; one engine reply is one undo step (`Editor.batch`, Lexical's history-push tag). A whole text from outside (the stored draft, another tab's save, the intro) comes in through `Editor.setMarkdown`, tagged `LOAD_TAG`, which resets the history with that text as its first state (`CLEAR_HISTORY_COMMAND` leaves none, and the first edit after it could not be undone). `deleteBefore` counts Unicode scalars, not Lexical's graphemes: a combining tone mark is one of its own. A caret the page places takes the text's own format, unless one was armed there (Command+B with nothing selected). The writes of one reply run inside its update (`Editor.batch`): a nested Lexical update would only be queued, and a write could not answer whether it took.
- Every engine call after startup goes through `call` in `ime.js`, which turns a trap into a new instance; `start` handles its own, because a trap there would only repeat. A new instance needs a new copy of the glue module (`loader.js`): the glue keeps the instance it has.
- A caret or text change the page did not make is found by comparing at the next key (`Surface.takeForeignChange`: the selection's points and the text, not Lexical's state identity, which a normalised selection also changes), not by `selectionchange`, which is asynchronous and fires on a different target per engine.
- The engine has every key first: its `keydown` listener captures on `#editor`, and a key it handled is `preventDefault`ed, which Lexical's `KEY_DOWN_COMMAND` handler at critical priority answers by skipping it (no Enter paragraph, no Backspace, no shortcut). The URL field in the format bubble sits inside `#editor` too; its keys are its own. Lexical takes Command/Control+B, I, U and Z itself; the page adds K for a link.
- One settings document, `taigi.settings`, in desktop's shape and key spellings (`settings.js`). A form control is named after its key and its markup default is that key's default; the session is the judge of a stored document. A chord's write comes back in the reply and goes through `Settings.adopt`, so the form and storage follow it.
- `<html>` carries the first visit's font and closed sidebar, which also stand when storage is blocked. `prepaint.js` restores the theme, the font, the key panel's room and the sidebar before first paint. It is the first child of `<body>`: as an external script in `<head>`, on either side of the stylesheet, WebKit left `body` on stale or missing rules in up to 4 of 10 reloads, which a first load does not show and parallel load brings out. Found by bisecting in Playwright's WebKit (`--repeat-each`); the mechanism is not known.
- A control the desktop settings window has takes the desktop's key for it, label and options alike: add `web` to that key's `scope.platforms`, never a `web.*` twin (maintainer 2026-11-07). A `web.*` key is only for text no desktop surface has (the editor, the load states, Other Resources).
- UI text comes from `i18n/*.json` through `web/src/generated/strings.js` (`make i18n`). An element names its key in `data-i18n` or `data-i18n-<attribute>`, `namespace.key`. The markup's English holds the layout and stays unseen until `setDisplayLanguage` has run, which `Settings` does before anything else draws. Text from the session arrives already translated, by the same `displayLanguage` setting and locale. `effectiveLanguage` in `i18n.js` is a twin of `DisplayLanguage::from_tag` + `effective`, because the page draws before the engine has loaded.
- Fonts are CJK-only by `unicode-range`, which also keeps an installed copy off romanization: these fonts misplace combining tone marks. Every face repeats one range, and `subset-fonts.sh` reads it from `fonts.css`. `data-font` picks the face through `--font`, so a face the setting does not name is never fetched. Iansui, the default, is in the service worker's shell so it works offline from the first visit (2.7 MB on that visit); the others are cached on first use.
- `#message` is read aloud, never drawn (`.unseen`). `#notice` is read aloud and drawn: from `compositionstart` to `compositionend` it takes the mode's place in `#mode-line`, the chip solid, because a composition the browser keeps open looks like a page that ignores its keys. Every drawn state has a slot in the layout (`#load-slot`), so nothing that appears shifts the page. The panel flips above the caret's line rather than pass the editor's bottom.
- Learning (`learning.js`): the engine's four stores are SQLite files in its memory VFS under `/taigi`; the page keeps their bytes in IndexedDB `taigi-web-user-data`, one record, so a save is one write. Only the tab holding the Web Lock `taigi-user-data` hands them in (`importUserData`, before `openUserData`, once per instance) and saves them right after each key that commits; another tab types without learning until the lock passes. Nothing is saved on the way out: Chromium, Firefox and WebKit all abort an IndexedDB write still running when the page unloads. Engine calls go through `ime.js` `run`, so a trap starts a new instance, which hands in the last copy; a trap while handing it in stops learning for the tab and leaves the copy alone. Playwright's WebKit keeps a page's Web Lock after `close({ runBeforeUnload: true })`, so tests close plainly. The origin is shared with the other sites on `taigikeyboard.tw`, which can read what the page stores.
- The TPS key panel's state is the desktop setting `tpsKeyboardShown` in the same document, so a chord and the sidebar row are one value. Its caps are out of the tab order: a keyboard user has the key itself. Clicks and `mousedown` keep focus in the editor, and a pointer on the panel does not end the composition.
- The Telex guide is the macOS card (`TelexGuidePanel.swift`), not a lookup table: the session sets `EngineState::draws_telex_guide`, so its table never carries the guide, and the page draws `#telex-guide` (`telex_guide.js`) from `telexGuide()`, floating over the editor's bottom centre as the macOS card floats over the screen's: it moves nothing, takes no clicks, and the candidate panel draws over it. It is up while the desktop setting `telexGuideShown` is on and TPS is not typed, beside the candidate list; only its chord flips it.
- `#spoken` is the live region for the candidate list, outside `#panel`, whose `hidden` would silence it. Focus never leaves the editor, so it says one cell rather than the page.
- `dev.html` is the segmentation and ranking view (`inspector.js`), titled Ranking Engine Lab. Its input settings, custom dictionary and the Sort Rules section sit in the same docked sidebar as the writing page (`sidebar.js`, `localStorage` `taigi.sidebar`). The main column uses the writing page's measure. It draws every candidate row, eight at a time. The writing page does not link to it and does not draw `explain`. The dev page uses the same session, the same `taigi.settings` document and the same learned data, and redraws the mechanism on every key. Its Display Language menu is Automatic, Hanji, English and Japanese: a stored Tâi-lô or Pe̍h-ōe-jī tag stays in the document for the writing page and this page draws Hanji instead. Dragging the twelve stages calls `setSortOrder`, a thread-local order in `ranking` that this page alone sets; the writing page and the official input methods never set it, so their comparison stays the field order of `CandidateSortKey`. The note is `sessionStorage` `taigi.devSortOrder`. Sort Rules offers Original (the built-in order, one-word ranking off), Jianzhong Proposal (preference, then a partial prefix after a full syllable or an abbreviation, then selection weight, then abbreviation, one-word ranking on), and Test, which is selected when the user reorders a stage or flips the switch (`sessionStorage` `taigi.devSortPreset`). Rank a one-word sentence calls `setRankOneWord`, the same kind of thread-local switch (`sessionStorage` `taigi.devRankOneWord`): a one-word best path joins the twelve stages. Delete Learning Records empties word frequency, next-word association and learned phrases, then `Learning.scheduleSave` writes that empty copy over the tab's IndexedDB snapshot. Custom words stay. The same page adds and deletes custom words (`saveCustomEntry`, `deleteCustomEntry`); they are the writing page's custom dictionary, and `Learning.scheduleSave` keeps them in that snapshot.
- The page is ZenPen's (zenpen.io, maintainer 2026-11-09): no box around the text, one centered column, no Copy or Clear, and the editor takes the window's height left over and scrolls inside it (`#editor` and `#text` are flex items with a zero basis: `flex: 1`'s 0% reads as the content against the body's indefinite height, and the text would stretch the page), so the TPS key panel stays on screen. The column is ZenPen's 600px, the colours its `.yin` / `.yang`, the title its 38px bold header, and the text its 22px / 30px article; blocks keep one blank line (30px) between them, headings and quotes set their line heights in px for the panel.
- The one thing drawn around the text is `#mode-line`, a chip at the right of the row under the editor (`.actions`, which keeps its room, so nothing moves; maintainer 2026-11-10, after a Shift tap into English mode read as a broken page). Black, white and grey only. Taigi mode: an outlined grey chip naming the mode and the input script. English mode: a solid chip (`--text` on `--bg` reversed) naming the mode and, behind a ⇧ cap, Taigi. The session spells it (`modeLine()`, `reply.rs` `mode_line_json`); the page redraws it on `modeChanged`, a settings change and a new instance.
- As ZenPen's `loadState` does, an empty text — a first visit, or one the user emptied — opens on `web.intro` (`Draft`, `draft.js`), in the display language, which a language change redraws until the first edit. The user deletes it and writes. The caret starts at the text's end. Its last paragraph, the maintainer's signature, is right-aligned (a paragraph format, not stored).
- The text is kept in `localStorage` `taigi.document` as Markdown (`draft.js`, `markdown.js`). A visit with none reads the textarea's plain text from `taigi.text` as plain text (`fromPlainText`: its paragraphs, every marker character escaped, so `1. ` or `*x*` stays text) and leaves that key as it was; an emptied `taigi.document` (`""`) stays empty, never falling back. It saves after each update that changed the text (not only the selection) and is not tagged `LOAD_TAG`, after a 300 ms pause, and on `pagehide` and a hidden tab when a save is pending. Another tab's save (a `storage` event) comes in through `setMarkdown` when it differs from this tab's text; being a load, it is not saved back, so two tabs never bounce a text between them. Writing reads back as the same blocks (fuzzed); spaces at a span's ends move outside its markers, and an empty paragraph goes.
- The title is `contenteditable="plaintext-only"` (`header.js`), edited or deleted in place as ZenPen's header is, and stored as `localStorage` `taigi.title`. `keepTitle` runs before `Settings` translates, and `#title` stays unseen until then. Keys there go to the title, not the engine; Enter moves to the editor, its caret where it was. An emptied title keeps its line, so a click writes it again, and opens on the default title at the next visit.
- The format bubble (`format_bubble.js`, maintainer 2026-11-10; the set after ZenPen and Calmly Writer) shows over a selection in the editor, never over a composition (the engine's, `panel.isShown`, or another input method's): H1–H3, bold, italic, underline, quote, bulleted and numbered lists, and link, as Lexical formats (`Editor.toggleFormat` / `toggleBlock` / `toggleList`, `$toggleLink`); each turns off again when the whole selection already has it; a list turns off whole (Lexical's `REMOVE_LIST_COMMAND`), not item by item. The link button turns the bubble into a URL field in place, and closes it again; the selection is kept while the field has focus and comes back on Enter or Escape; nothing is written when the text changed meanwhile. `normalizeUrl` adds `https://` unless a `scheme://`, `mailto:` or `tel:` is there, and percent-encodes `()<>` and whitespace. The bubble is absolutely placed with no transition, so nothing moves when it shows; it is the page's one selection-driven overlay. A `mousedown` on it, the URL field aside, keeps the focus in the editor. Its icons are Font Awesome Free, as the footer's, H1–H3 their own labels, with no aria-label or tooltip and the URL field's placeholder a bare `https://`: no i18n key for the bubble (maintainer 2026-11-10, "as lean as possible"). The web editor is meant to stay Apple Notes-simple: no fullscreen or word-count target (maintainer 2026-11-10).
- Save (sidebar, `save.js`) downloads the title and the text, as ZenPen's `formatText` does: `.md` (`# title`, then the stored Markdown), `.html` (`<h1>`, then the blocks: `<h1>`–`<h3>`, `<blockquote><p>`, `<ul>` / `<ol start>`, `<p>` with `<br>` per line break, `<strong>` / `<em>` / `<u>`, and links to `http:` / `https:` / `mailto:` only, any other link left as its text; a text with no markers comes out as it did from the textarea, fuzzed) or `.txt` (the title, a blank line, the text without markers, list items keeping their bullet or number), named after the title (`台語齒盤` when it is empty), through a `blob:` link: the CSP does not govern a download.
- WebKit on a Mac skips buttons on Tab by default, so tab-order tests run in Chromium and Firefox only.
- Lexical's history merges edits less than 300 ms apart; an engine reply always starts a step of its own.

## ChromeOS input method

- `web/chromeos/` is a Manifest V3 extension over the same `taigi-web` bindings: `worker.js` takes `chrome.input.ime` events, `calls.js` (pure, Node-tested) turns ChromeOS keys into `BrowserKey` JSON and replies into `chrome.input.ime` calls. `make -C web chromeos` stages `web/target/chromeos/` and zips it. Design and spike: `docs/architecture/chromeos-roadmap.md`.
- ChromeOS confirms the preedit into the field itself on blur and reset, as Linux frameworks do, so the worker calls `endSession` there (the engine drops its copy, no commit) and `beginSession` on focus.
- A key never wakes a stopped worker; `offscreen.html` messages it every 20 s so it never stops. Never remove the keepalive without re-running the idle test on ChromeOS.
- ChromeOS names some keys its own way (`Down`, `Esc`, `Ctrl`, `""` for Delete): `calls.js` reads those by `code`. A reply carries the whole candidate list; ChromeOS is sent the cursor's page, with page-relative IDs, which is what `clickCandidate` takes. The preedit caret goes out in UTF-16 units.
- The options page is the page's settings form, cut at build time by `chromeos/options-form.mjs` into `chromeos/options.html` (`scripts/stage-chromeos.mjs`). A row ChromeOS cannot honour is `hidden`, never removed (`Settings.#show` reads every control); a name the cut cannot find fails `make -C web chromeos`, so a renamed control in `index.html` shows up there. `Settings` takes its store as a parameter: the page keeps `localStorage`, the options page and the worker share `chrome.storage.sync` under `taigi.settings`. The worker writes the composition before it takes a new document, as `ime.js` `changeSettings` does, and skips a document equal to the one it holds, so its own chord writes do not come back.
- The worker imports the page's `learning.js` and `settings.js` as they are, so neither may touch the DOM at load. Every engine call goes through the worker's `run`. A service worker cannot `import()`, so it cannot load the fresh glue copy a new instance needs (`loader.js`): after a trap the worker stops its keepalive, ChromeOS stops it, and the next focus starts a new worker. Keys typed in between reach the field unhandled; whether key events also hold the stopping worker longer is not verified.
- `onKeyEvent` takes one listener. Google Docs and X send `onReset` while typing; `isResetStorm` skips those (from McBopomofoWeb, unverified here).
- Dev loop without a Chromebook: Chromium's `Linux_ChromiumOS_Full` snapshot in an Apple Virtualization Linux VM with Rosetta (recipe in the roadmap's § Spike result). Chrome keeps an unpacked extension's service worker across restarts, so after a rebuild start from a new profile, or the old worker runs.

## Browser extension

- `web/extension/` is a Manifest V3 extension that types into websites' own fields. Design, the fields it supports and its known limits: `docs/architecture/browser-extension.md`. `make -C web extension` stages `web/target/extension/` and zips it; `make -C web extension-e2e` is its browser gate.
- The engine runs in the tab (`typing.js`, the twin of `ime.js`), never in the service worker: `preventDefault` must run during `keydown`. `content.js` is all a page gets until typing is turned on in its tab; nothing else may be added to it.
- `content.js` adds the window's `keydown` / `keyup` capture listeners at `document_start`, so they are the first. A key the engine took is `preventDefault`ed and `stopImmediatePropagation`ed, and so is its release: a site must not act on the Enter that picked a candidate.
- One write path into a site's field: `execCommand` through `field.js`. Never assign `value` or edit the DOM of a site's editor: both lose its undo history.
- The page's `panel.js`, `surface.js`, `i18n.js`, `settings.js` and `style.css` ship in the extension as they are, and its panel markup and settings form are cut from `index.html` at build time (`scripts/stage-extension.mjs`). None of them may touch the page's own DOM at load, and a renamed element in `index.html` fails `make -C web extension`.
- Everything the extension draws is in one open shadow tree under `<taigi-keyboard>`, appended to `<html>`. The host's own style is inline and `!important`; `#box` resets inheritance with `all: initial`.
- A site's Content Security Policy does not stop the extension's modules, styles or `fetch`, but it does stop `WebAssembly.compile` in a content script. Such a site shows **Could not load** and keeps its keys.
- The settings document is `chrome.storage.sync` `taigi.settings`, as on ChromeOS; the options page is `chromeos/options.js` over the extension's cut of the form. A tab's mode is `chrome.storage.session`; the learned data is the service worker's IndexedDB (`learning-store.js`), and a content script reaches it only by message.
- A message handler in `background.js` answers only this extension's own senders, and refuses a private tab's learning messages.
- Tests give the copy under test its sites in the manifest, because the browser's permission dialog cannot be answered by a harness. The grant itself is checked by hand.

## Tests

- Native tests cover the session and the key translation, with no lexicon. The engine is one per process, so a test that asserts what it composed takes the `ENGINE` turn and leaves it idle (`taigi-web` `session.rs`, `desktop/crates/taigi-desktop-core/tests/session_language_mode.rs`).
- The smoke test (`web/tests/`) drives the real engine and real dictionaries through the bindings the page loads, one key at a time, with `wasm-bindgen --target web` + `initSync`.
- Expected values come from `engine/composing/tests/` fixtures, whose traces are recorded there. Never from `corpus/`, which feeds no test (`corpus/README.md`).
- Passing in Node says nothing about a browser, a low-end machine or DOM cost. Playwright (`web/e2e/`) sends real keystrokes to the staged site in Chromium, Firefox and WebKit, one test per row of the roadmap's § Text surface.
- A request from a page under a service worker never reaches `page.route`, so a test that routes after a first load uses `test.use({ serviceWorkers: "block" })`. A page in a test is under one only after a reload or a second tab.
- A reload is served by the old worker, so a test of a new version closes every tab first (`offline.spec.mjs`).
- Playwright types on a US layout, so Option and AltGr rewrites never reach it; `key.rs`'s table tests cover those.
- A form control's default is its markup: `selected` or `checked`. `data-boolean` marks a select over a stored boolean, `data-requires` a checkbox that greys, keeping its value, while the one it names is off.
- `/` focuses the editor, without selecting: a selection would let the next key replace the document.
- The session measures the expandable layouts during a key, through `globalThis.taigiMeasureCells` (`Panel.measure`, `layout.rs`; `docs/architecture/web-roadmap.md` § Candidate window width source). `#ruler` sits outside `#panel`: `#panel[hidden]` is `display:none`, and the first key of a word measures before the panel shows. The import is `catch`: an exception through `&mut self` skips its drop and every later call is refused. Nothing it runs may call the session.
- One reply can carry two tables, so `layout` goes on the last one with a highlight. A reader of `reply.rs` should not assume one table per reply.
- The candidate panel's lengths are one formula over `--candidate-size`, so `Settings` sets that one property. `LookupTable` carries `cells`, the two scripts apart; `joined_candidates` is for panels with one text column (IBus, Fcitx5).
