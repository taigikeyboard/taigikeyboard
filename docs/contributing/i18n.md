# i18n Source Rules

`i18n/*.json` keys are **shared across platforms** — each key's `scope.platforms` decides which native resources `make i18n` emits. A single-platform round that deletes a key can break another platform's build on `main`. Pull-request CI compiles only Android (`android.yml`) and macOS (`macos.yml`) on an `i18n/**` change; an iOS, Windows or Linux break shows up only in that platform's local gate.

- Before deleting a key, grep every platform for **every** generated name (`tools/i18n/i18n_lib.py` name transforms) — the JSON key alone misses them. For `settings.resetFailed`:

  | Name | Form | Used by |
  |---|---|---|
  | `settingsResetFailed` | `<namespace><KeyName>` (`l10n_accessor`) | Android `L10n`, iOS / macOS Swift |
  | `SETTINGS_RESET_FAILED` | `NAMESPACE_KEY_NAME` (`string_key_const`) | Android `StringKey` enum |
  | `SettingsResetFailed` | `<Namespace><KeyName>` | desktop-core / Windows / Linux `StringKey` |
  | `i18n_settings_resetFailed` | `i18n_<namespace>_<key>` (`res_name`) | Android `R.string` |

  ```sh
  grep -rnE "settingsResetFailed|SETTINGS_RESET_FAILED|SettingsResetFailed|i18n_settings_resetFailed" \
    ios/Sources android/app/src/main/java macos/Sources windows/ desktop/ linux/ \
    | grep -v -e '/generated/' -e '/Generated/' -e 'strings/generated.rs'
  ```

  Any hit outside the generated files is a live consumer: drop only your platform from `scope.platforms`, or keep the key. `make i18n` and its staleness check cannot catch a deleted key that is still used — the regenerated outputs are consistent; only the consumer's compile fails.
- Any round touching `i18n/**` runs the post-PR gate for **every platform listed in the touched keys' `scope.platforms`**, not only the round's own platform.
- Read gate logs, not background-task exit codes — a trailing `echo` masks failures.
