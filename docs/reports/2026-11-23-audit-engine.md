## 1. Summary

The engine is in better shape than on 2026-11-13: E1 (one `FetchAtPos` path), E2 (dispatch applies the next-word handshakes), E3 (all five multi-concern files split) and most of E4 merged, and no finding reaches High. The largest remaining cost is surface that runs but does nothing: two phonetics ops no platform sends (`TlToPoj`, `TlDisplayToTps`), a nail / unnail handshake that travels composing → dispatch → nextword only to return `result_unchanged`, a `RecordUsage` op kept only to seed tests, and 233 lines of mode-keyed case tables whose output is byte-identical to stdlib casing — which also makes three case-routing tests unable to fail. Close behind: 17 source comments that contradict the code (15 cite a "Core Principle #7" that does not exist) and a `rust-core-proto.md` op-count table where 4 of 6 counts are wrong. **Recommended first round: R1, the dead-op + no-op-handshake removal (~−250 LOC, engine + bridges)**, since every later cleanup of `nextword` / `phonetics` gets smaller after it.

## 5. Open USER decisions (ranked)

1. **Case `mode` on the wire.** After R2 the `mode` field on `ToneCase` / `TransformInputCase` changes nothing. Options: keep it (engine-only R2), or `reserved` it and drop it from the iOS / Android / desktop-core senders. Recommendation: keep it in R2, drop it in R7 so R2 stays a pure engine refactor.

3. **Bit-13 legacy all-on + absent-subcollections path** (carried from 11-13 decision 6). Recommendation: remove in R7 with a contract note — every shell sends both.
4. **e2e-trace opener on iOS / Android.** Exported, never called, no e2e harness for mobile. Recommendation: remove the two exports and fix `e2e-trace-schema.md`; re-add when a mobile e2e driver exists.
5. **Banner deletion churn** (~245 lines across 40+ files). Recommendation: yes, one comment-only PR (R4); `git blame` noise is the only cost.
