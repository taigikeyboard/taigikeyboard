## 1. Summary

The engine crate graph is clean: no upward edges, and both FFI crates depend only on `dispatch` + `protos`. The cost now sits in three places.

1. **Windows still runs its own copy of the desktop key path.** About 900 lines in `session.rs` cover global chords, the symbol picker, English mode and `perform_global`. Linux and web already call desktop-core `process_key` / `perform_global`. The copy has already drifted, which gives two bug candidates (§2.2).
2. **The engine still lets shells orchestrate.** A commit takes two FFI hops (E2). `FetchAtPos` runs on two parallel paths, and its reach-throughs into store fields grew from 5 to 10 (E1). Candidate split / dedupe is written three times (D4).
3. **Five engine files hold several concerns each** (E3). All of them grew since October; `continuous.rs` is now 1,730 production lines.

New dead surface is small (~300 LOC): two `DecideResult` fields, the Linux `taigi_reply_table_*` C accessors, and macOS migrations for defaults and keys that never shipped in a tagged release.

**Recommended first round:** R1, dead-code removal (§4). It has no observable behaviour change, it is mostly deletions, and every row in it was verified.

## 3. Justified-looking layers (do not re-flag)

- Engine crate graph: no upward edges, and the FFI crates see only `dispatch` + `protos`.
- Windows / Linux settings + TSF crates depend on `dispatch` only to unify the `user-data` cargo feature (commented in place).
- Traits / protocols / interfaces that look like single-implementation wrappers: almost all of them have a test fake or a no-op preview implementation.
- `FilterPredictions` has no platform sender; it is an accepted internal target.
- Android `dispatchLog` JNI callback, and the integration-test seams (`KeyEventSnapshot::with_key_code`, Linux settings `current_pane` etc.): they are `pub` because separate test crates call them. `#[doc(hidden)]` at most.
- iOS / Android `retireLegacyAppearance` / `LegacyAppearance`: v3.5.x wrote those keys. `hyphenlessRomanEnabled` carry: shipped in mobile-3.6.13 / 3.7.0. Frequency `tl == ""` bucket: user data. `CaseTransform` `fallback = input`: an FFI-failure guard, logged.
- Android SharedPreferences → DataStore migration (`PrefHelper.kt:919`): unreachability cannot be proven.
- `association_roman` raw path: still needed for TPS-OOV (fix the comment only).
- macOS `SettingsStore` Swift schema (`SettingsStore.swift:41-400`): no drift today, and the UserDefaults layer stays in Swift. Only the defaults could come from core.
- Carried over: ranker `(display, "")` bucket; ~82 platform restatement tests (R7-2b); shared Swift package rejected; macOS geometry / update flow scoped out; one FFI header rejected.

## 5. Open USER decisions (ranked)

1. **Round order.** Recommendation: R1 → R2 → R4 → R5 → R6 (all no-behaviour-change, low risk); stop there and re-decide before R7+.
2. **Windows bug candidates.** Dogfood the backtick / password-field picker on the Windows box first. Recommendation: confirm on device, then fold the fixes into R9 as declared parity corrections.
3. **Android English pick `hhello`.** Recommendation: run the 5-key device check; if it reproduces, open a separate bugfix round (Android only).
4. **Carried from 2026-10 (still open):** decision 2 (roman-only custom words on phones; recommend yes); decision 3 (E2 one-hop contract; recommend yes, after D-rounds); decisions 7–8 (English split = Android's, ISO date + whole number ≥ 1; recommend yes).
5. **Missing invariant labels §36 / §38.** Recommendation: attach each label to an existing test if one covers the behaviour; otherwise drop the label from the doc.
6. **Engine bit-13 "legacy all-on" path.** Removing it is a contract change, because an unset gate would no longer mean all-on. Recommendation: remove in R8 with a contract note, since every caller sends the gate.
