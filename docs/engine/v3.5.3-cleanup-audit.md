# v3.5.3 — engine workspace cleanup audit

> **Status**: pre-flight audit, post-Codex review. 2026-04-29.
> **Branch**: `phase4b/v3.5.3-engine-cleanup`.
> **Scope**: refactor-only; zero behavior change.

## Why

v3.5.2 shipped two independent slices:

- PR #189 — Lexicon Ranking → Rust shared core (new `engine/ranking` crate, `engine/dispatch` envelope router, `lexicon.proto`).
- PR #190 — phonetics post-slice cleanup (split `derivation.rs` → `derivation` + `normalization`, collapsed `pub mod` → `mod` for impl modules, dropped top-level `process_request` re-export, established `rules/rust-best-practices.md §3a` domain↔proto boundary rule).

After PR #190 the workspace has **two** domain crates following the §3a façade pattern. A workspace-wide read of every `engine/**.rs` surfaced cross-cutting cohesion / naming gaps that no single slice owns:

1. `phonetics::api` still contains a duplicate FFI envelope (decode top-level `Request` → catch_unwind → encode `Response`) that overlaps `engine/dispatch::process_request`. The phonetics-internal one even rejects Lexicon payloads as `FailInvariant` — a stale phonetics-only envelope superseded by the canonical dispatcher (§3a §95: a per-domain `process_request` inside the domain crate is the same anti-pattern as the explicitly-banned `dispatch::process_phonetics`).
2. Test file names (`d9_4_cleanup.rs`, `d9_4_ops.rs`) embed sub-round project history rather than describing the behavior they pin.
3. Two functions named `nfd_preprocessed` exist with **different semantics** — `ranking::nfd::nfd_preprocessed` (codepoint replacement, ignores adjacency) vs `phonetics::normalization::nfd_preprocessed` (literal `o\u{0358}` adjacency-substitution for trie keys). The conflicting names cause cross-crate ambiguity; `ranking::nfd` even self-flags this in a comment.
4. `engine/protos/src/lib.rs` re-exports `pub use engine::*` that no caller uses (every callsite says `protos::engine::Foo`).
5. `phonetics/src/parser.rs` is misnamed — every function operates at the syllable level (`strip_tone_mark`, `normalize_to_tl`, `is_stop_tone`, `split_initial_final`, `parse_syllable`).
6. `phonetics/src/tables.rs` co-locates four unrelated table groups, including the Zhuyin tables that are TPS-only and have a natural home next to `tps.rs`.
7. `MAX_REQUEST_BYTES` is duplicated verbatim in `swift-ffi` and `android-jni` with a "both crates must agree" comment — the value should have a single source of truth.

The user goals for the slice are explicit:

1. Rust 模組內聚力高、外部依賴小 — high cohesion, minimal external deps.
2. 符合最佳實踐 — best-practices alignment.
3. 檔案名稱、函數變數名稱職責專一 — single-responsibility filenames + identifier names.

## Goals + non-goals

**Goals.**

- Every change preserves observable behavior. `cargo test --workspace` plus `cargo clippy --workspace --all-targets -- -D warnings` are green at every commit boundary.
- Cohesion: cull duplicate FFI envelopes, narrow public surfaces to what callers actually use.
- Dependency minimization: when a public function disappears, drop the dependency it brought in (Codex P1: phonetics's `prost` becomes dev-only after the envelope leaves).
- Naming: filenames match the responsibility they own (`syllable.rs` for syllable parsing); function names describe purpose, not implementation detail (`taigi_unicode_base_form` instead of `nfd_preprocessed`).
- Test layering: tests live with the code they exercise. Domain tests against `phonetics::dispatch::handle`; envelope tests against `engine/dispatch`.

**Non-goals.**

- New module migration. Composing (D9.3) stays deferred to v3.5.4 per `project_rust_migration_cadence.md`.
- Schema or wire-format changes — `engine/protos/proto/*.proto` is untouched.
- Cross-platform behavior changes — Swift / Kotlin call sites recompile against the same `RustEngineBridge` API.
- Renaming the `engine/dispatch` crate or the `phonetics::dispatch` module. The naming overlap is real but every callsite is fully qualified and §3a documents the layering; renaming is churn for a marginal gain.
- Splitting `tables.rs` into a four-file submodule directory. Option (a) below — moving Zhuyin into `tps.rs` only — captures the cohesion win without quadrupling the file count.
- Internal-candidate-type decoupling in `ranking` (deferred from v3.5.2 as premature without a second op forcing it; still premature).

## Commit slicing

Twelve refactor-only commits, ordered to minimize merge conflicts and keep `cargo test --workspace` green at every boundary. The first eleven are the planned implementation; the twelfth is a follow-up rustfmt sweep on files this slice authored, scoped per PR #190's policy.

1. **docs** — this file (`docs/engine/v3.5.3-cleanup-audit.md`).
2. **protos** — drop dead `pub use engine::*`. No-op for callers; tightens surface.
3. **tests rename** — `d9_4_cleanup.rs` → `normalize_tone_nasal_case.rs`; `d9_4_ops.rs` → `op_coverage.rs`; rewrite both headers to describe the behavior they pin.
4. **NFD rename** — `ranking::nfd::nfd_preprocessed` → `taigi_unicode_base_form`; `phonetics::normalization::nfd_preprocessed` → `trie_key_unicode_form`. Fix the stale `ranking::nfd` comment that still says `phonetics::derivation::nfd_preprocessed` (the function moved to `normalization` in PR #190).
5. **op tests migration** — `empty.rs` / `op_coverage.rs` / `normalize_tone_nasal_case.rs` / `roundtrip.rs` / `invariants.rs` switch from `phonetics::api::process_request(bytes) → Vec<u8>` to `phonetics::dispatch::handle(&PhoneticsRequest, &AppConfig) → Result<PhoneticsResponse, PhoneticsError>`. Assertions move from `Response.id/error/payload` to `Result<PhoneticsResponse>`.
6. **envelope tests move** — `panic.rs` / `malformed.rs` / `oversized.rs` / `logging.rs` move from `engine/phonetics/tests/` to `engine/dispatch/tests/`. Panic injection becomes a private `#[cfg(test)]` seam inside `engine/dispatch/src/lib.rs`; the previously-public `phonetics::api::process_request_with` goes away in commit 7.
7. **delete envelope** — remove `process_request`, `process_request_with`, `run_request`, `error_response`, `error_code_for`, `encode_response` from `engine/phonetics/src/api.rs` (~120 LOC). Remove `PhoneticsError::InvalidProto` (no remaining producer). Drop `prost` from `engine/phonetics/Cargo.toml` (now unused). Clean stale comments in `engine/phonetics/src/lib.rs` referencing the removed FFI entries. Audit top-level re-exports.
8. **rename `parser.rs` → `syllable.rs`** — file move + `mod parser` → `mod syllable` + update §3a canonical example.
9. **Zhuyin tables move** — `ZHUYIN_INITIALS` / `ZHUYIN_VOWELS` / `ZHUYIN_TONES` / `ZHUYIN_TONES_ENCODE_SAFE` / `PUNCTUATION_PAIRS` (TPS-only) move from `tables.rs` into `tps.rs`. `PUNCTUATION_CHARS` stays in `tables.rs` if it has a non-TPS caller; otherwise also moves.
10. **`MAX_REQUEST_BYTES` SSOT** — `pub const MAX_REQUEST_BYTES: usize = 2 * 1024 * 1024;` declared in `engine/dispatch/src/lib.rs`; `swift-ffi` and `android-jni` import via `use dispatch::MAX_REQUEST_BYTES`. Pre-allocation early-reject behavior preserved on Android.
11. **§3a doc update** — `rules/rust-best-practices.md §3a` canonical example block reflects `mod syllable` (not `mod parser`); remove stale references to `phonetics::api::process_request` if any.
12. **fmt sweep** — `rustfmt` applied to files this slice authored. Pre-existing fmt drift in files this slice only marginally edited (one-line import path renames in `case_adjust.rs` / `dispatch.rs` / `tps_adjust.rs`) is intentionally left alone, mirroring PR #190's policy.

## Verification gate

At every commit:

```sh
cd engine && cargo test --workspace
cd engine && cargo clippy --workspace --all-targets -- -D warnings
```

Both must be green. Behavior-change risk is structural (renames, file moves, dependency adjustments) and detectable by the existing test corpus — no new tests added, no fixtures modified. The xcframework + jniLibs builds are user-handled per `feedback_manual_build_test.md`; refactor-only changes that compile against the same proto schema do not require regeneration.

## Risks

- **`prost` dep removal (commit 7)** must come *after* envelope deletion *and* `PhoneticsError::InvalidProto` removal. If a stray caller still produces `InvalidProto`, the dep cannot be dropped. Verified by grep at audit time: `prost::DecodeError` only appears inside the envelope being deleted.
- **Test migration order** — commits 5 and 6 must precede commit 7. If the envelope is deleted while any `phonetics/tests/*.rs` still calls `phonetics::api::process_request`, `cargo test` breaks.
- **Zhuyin tables move (commit 9)** — every caller of `ZHUYIN_*` constants currently lives in `tps.rs` itself or in `tps_adjust.rs`. The move is a pure relocation of `pub(crate)` items; if any cross-module caller exists, surface during the commit.
- **`MAX_REQUEST_BYTES` SSOT (commit 10)** must keep the early-reject pre-allocation pattern on Android. The constant moves; the Android `get_array_length` pre-check stays.

## Out of scope (no version commitment)

- `engine/composing` crate creation + Composing intents + `Mutex<Engine>` + `EngineHandle` lifecycle — v3.5.4 D9.3.
- Internal candidate type in `ranking` to decouple from `protos::engine::TaigiWord` — premature without a second consumer.
- Splitting `phonetics/src/dispatch.rs` `handle` match into per-op functions — current is idiomatic Rust.
- Moving `phonetics/src/dispatch.rs` `parse_input_mode` / `preprocess_for_normalize_tone` / `convert_nasal_double_n` into a dedicated `tone_normalize.rs` — current cohesion is fine.
- Renaming `engine/dispatch` crate or `phonetics::dispatch` module — naming overlap is acceptable given §3a documentation.
