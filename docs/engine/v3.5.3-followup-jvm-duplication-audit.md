# v3.5.3 follow-up — JVM duplication cleanup audit

> **Status**: pre-flight audit, post-Codex inventory. 2026-04-29.
> **Branch**: `phase4b/v3.5.4-jvm-duplication-cleanup` (branch name retained from initial misnaming; PR #192 title corrected to v3.5.3 follow-up).
> **Scope**: refactor-only; zero runtime behavior change on the success path. Lands as a continuation of the v3.5.3 release window started by PR #191.

## Why

After PR #191 the engine workspace was internally clean, but ~660 LOC of platform Kotlin/Swift still mirror Rust algorithms verbatim. The mirrors exist for one root cause: **Android `src/test/` JVM unit tests cannot load `librust_taigi.so`** (per the now-obsolete `feedback_jvm_test_jni_compat.md` / PR #187 strategy). iOS Swift mirrors followed for parity.

User opted for **path G — delete the duplicates rather than build JVM-loadable Rust artifacts**. Rationale:

- Solo maintainer; real-device dogfood is the production gate.
- Rust workspace already has 154+ tests covering algorithm correctness.
- The reference IME `khiin-rs` ships with a 52-LOC `EngineManager.kt` bridge and zero Kotlin math + zero Kotlin math tests; same shape works for us.
- Adding host-target Rust cross-compile + `java.library.path` plumbing is long-term maintenance cost for a test tier the user does not run.

This slice deletes the A-class mirrors + their tests, plus four B-class JVM tests Codex confirmed have been silently build-broken since D9.4.

### Rust additions (2 ops)

**Op 1 — `ProcessCandidatesRequest.merge_order_only: bool = 8`**

Replaces iOS `LexiconService` cold-start fallback (`LexiconService.swift:241-245`):

```swift
// before — Kotlin/Swift mirror dedup, no scoring
let uniqueWords = CandidateProcessor.removeDuplicates(merged)
return isTPS ? CandidateProcessor.removeDisplayDuplicates(uniqueWords) : uniqueWords
```

Becomes a Rust round-trip with `merge_order_only=true`. Rust impl branches before scoring:

```
remove_duplicates(req.raw)
if req.tps_dedup_enabled { remove_display_duplicates(...) }
return ProcessCandidatesResponse { ranked, breakdown: [] }
```

**Op 2 — `PhoneticsRequest.method.nfd_preprocess_for_lookup` (tag 19)**

Replaces `TaigiUnicode.nfdPreprocessed(syllable)` call inside `ExternalLookupURLBuilder` on both platforms. NEW message:

```protobuf
message NfdPreprocessForLookup { string input = 1; }
```

Returns existing `StringResult`. The helper `taigi_unicode_base_form` consolidates from `engine/ranking/src/nfd.rs` into `engine/phonetics/src/normalization.rs` as `pub fn`; `engine/ranking` gains a `phonetics` workspace dep so `ranking::score::roman_to_base` continues to call the same algorithm. Dispatch handler reads `phonetics::normalization::taigi_unicode_base_form` directly.

**Why not reuse `Method::NormalizeInput`** (Codex evidence):
- `NormalizeInput` lowercases, converts tone marks → digits, adds default tones, splits syllables (`normalization.rs:21-47`)
- `taigi_unicode_base_form` is just NFD + nasal substitution + `\u{0358}` collapse — different output
- Rust source at `nfd.rs:11-16` already documents the two are non-interchangeable

## Risks

- **iOS cold-start ordering parity** — Rust merge-order dedup must produce byte-identical candidate order to the previous Swift `CandidateProcessor.removeDuplicates` + `removeDisplayDuplicates`. Pin via Rust unit tests covering custom-before-system merge order.
- **External lookup URL parity** — `taigi_unicode_base_form` must produce byte-identical output to `TaigiUnicode.nfdPreprocessed` for Taiwanese URL-encoded payloads. Pin via Rust unit tests covering nasal markers / `o͘` / repeated `o͘` / tone-combining retention.
- **Loss of FFI error-path graceful degradation** — accepted explicitly per Q3.
