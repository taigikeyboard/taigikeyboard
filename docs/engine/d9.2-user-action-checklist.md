# D9.2 — User-action checklist

The Rust + Kotlin + Swift code for D9.2 lands via PR. The remaining steps
require manual edits to `*.xcodeproj`, `*.gradle.kts`, and the Android
`Application` class (per `feedback_xcode_manual.md` AI does not edit those).

Run all of these on the local clone after pulling the D9.2 branch.

## 0 · One-time tooling install

```bash
brew install protobuf swift-protobuf      # protoc + protoc-gen-swift
cargo install cargo-ndk --locked          # arm64-v8a Rust → .so cross build
```

## 1 · Generate platform proto code

```bash
engine/scripts/gen-platform-protos.sh
```

Outputs:

- `ios/Sources/TaigiKeyboard/Engine/Generated/*.pb.swift`
- `android/app/src/main/java/com/siansiansu/taigikeyboard/engine/proto/*.java`

Commit the regenerated files.

## 2 · Build Rust artefacts

For the production build:

```bash
engine/scripts/build-xcframework.sh        # → ios/RustEngine/RustTaigi.{xcframework,swift}
engine/scripts/build-android-libs.sh       # → android/app/src/main/jniLibs/arm64-v8a/librust_taigi.so
```

For tests (T1 panic injector enabled):

```bash
engine/scripts/build-xcframework.sh --dev   # overrides ios/RustEngine/ with the dev build
engine/scripts/build-android-libs.sh --dev  # overrides librust_taigi.so with the dev build
```

Run the release scripts before shipping a Play Store / TestFlight build.

## 3 · iOS Xcode project edits

Open `ios/TaigiKeyboard.xcodeproj` in Xcode.

1. **Add SwiftProtobuf SPM package** to both `TaigiKeyboard` (main app) and
   `TaigiKeyboardExtension` (keyboard ext) targets:
   - File → Add Packages → `https://github.com/apple/swift-protobuf`
   - Version range: `1.27.0..<2.0.0`.

2. **Add the Rust xcframework**: drag `ios/RustEngine/RustTaigi.xcframework`
   into the Xcode project. Target membership: both `TaigiKeyboard` AND
   `TaigiKeyboardExtension`. Embed setting: "Embed & Sign" (extension
   target embeds via the host app — leave the extension on "Do Not Embed",
   only the host app embeds).

3. **Add the swift-bridge generated Swift wrapper**: drag
   `ios/RustEngine/RustTaigi.swift` (and `ios/RustEngine/SwiftBridgeCore.swift`
   if present) into BOTH targets' Sources build phase.

4. **Add the bridge module + tests**:
   - Drag `ios/Sources/TaigiKeyboard/Engine/RustEngineBridge.swift` into both
     `TaigiKeyboard` and `TaigiKeyboardExtension` targets.
   - Drag `ios/Sources/TaigiKeyboard/Engine/Generated/*.pb.swift` into both
     targets.
   - Drag `ios/TaigiKeyboardTests/RustEngineBridgeTests.swift` into the
     `TaigiKeyboardTests` target.

5. **Run tests** (after `build-xcframework-dev.sh` to enable T1):
   ```bash
   xcodebuild test -scheme TaigiKeyboard \
     -destination 'platform=iOS Simulator,name=iPhone 15 Pro' \
     -only-testing:TaigiKeyboardTests/RustEngineBridgeTests
   ```

## 4 · Android `build.gradle.kts` edits

In `android/app/build.gradle.kts`:

1. **Narrow `abiFilters`** (line 31, in the `defaultConfig.ndk` block):
   ```kotlin
   abiFilters += listOf("arm64-v8a")  // was: "arm64-v8a", "armeabi-v7a", "x86_64"
   ```
   *Justification:* Play Store has required 64-bit since 2019; minSdk 28
   excludes pre-arm64 hardware; user does not ship to Chromebook or
   x86_64 emulator. Documented in plan v4 §B9.

2. **Add the protobuf-javalite runtime** to `dependencies { ... }`:
   ```kotlin
   implementation("com.google.protobuf:protobuf-javalite:3.25.5")
   ```

3. **Configure the AndroidJUnit instrumentation runner** (in `defaultConfig`):
   ```kotlin
   testInstrumentationRunner = "androidx.test.runner.AndroidJUnitRunner"
   ```

4. **Add androidTest dependencies** (current stable):
   ```kotlin
   androidTestImplementation("androidx.test:runner:1.7.0")
   androidTestImplementation("androidx.test.ext:junit:1.3.0")
   ```

## 5 · Android Application wiring

Find the existing `Application` subclass (or create one and register it in
`AndroidManifest.xml` `<application android:name=".TaigiKeyboardApplication">`).
In `onCreate`, after the LoggerBackend is initialised:

```kotlin
import com.siansiansu.taigikeyboard.engine.RustEngineBridge

override fun onCreate() {
    super.onCreate()
    // ... existing init ...
    RustEngineBridge.install(loggerBackend)  // your DI-resolved LoggerBackend
}
```

If no Application subclass exists yet, the install can also be called from
`MainActivity.onCreate` — but the IME service might load `librust_taigi.so`
before then, so an Application subclass is the recommended location.

## 6 · Local gate sequence

```bash
# 0. From engine/, regenerate proto + cargo gate
cd engine
cargo fmt --all -- --check
cargo check --workspace --locked
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cd ..

# 1. Build dev artefacts (panic-injector ON for T1 / T6 tests)
engine/scripts/build-xcframework.sh --dev
engine/scripts/build-android-libs.sh --dev

# 2. Run platform tests
xcodebuild test -scheme TaigiKeyboard \
  -destination 'platform=iOS Simulator,name=iPhone 15 Pro' \
  -only-testing:TaigiKeyboardTests/RustEngineBridgeTests

# Real arm64-v8a device or arm64 emulator only — NOT x86_64.
./gradlew :app:connectedAndroidTest \
  --tests "com.siansiansu.taigikeyboard.engine.RustEngineBridgeTest"

# 3. Restore release artefacts before any TestFlight / Play Store build
engine/scripts/build-xcframework.sh
engine/scripts/build-android-libs.sh
```

## 7 · IME runtime impact

**None.** D9.2 only loads the Rust shared-core into the process and
verifies it via unit tests. The IME continues to use
`PhoneticsConverter.swift` / `TaigiPhonetics.kt` for production keystroke
handling. Production swap lands no earlier than D9.4 (after INVARIANT_*
parity tests prove behavioural equivalence).
