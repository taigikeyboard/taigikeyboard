# i18n Source Rules

`i18n/*.json` keys are **shared across platforms** — each key's `scope.platforms` decides which native resources `make i18n` emits. A single-platform round that deletes a key can break another platform's build on `main`, and no CI catches it.

- Before deleting a key, grep every platform for the generated accessor — `<namespace><KeyName>` camel-case (`dictionary.customDictEnabledInfo` → `dictionaryCustomDictEnabledInfo`):

  ```sh
  grep -rn "dictionaryCustomDictEnabledInfo" ios/Sources android/app macos/Sources windows/
  ```

  If any other platform uses it, drop only your platform from `scope.platforms`; never delete the key.
- Any round touching `i18n/**` runs the post-PR gate for **every platform listed in the touched keys' `scope.platforms`**, not only the round's own platform.
- Read gate logs, not background-task exit codes — a trailing `echo` masks failures.

Incident: PR #564 (`cd544dbc`, 2026-08-21) removed four macOS footers and deleted `customDictEnabledInfo` / `frequencyRecordingEnabledInfo` from `i18n/dictionary.json`; iOS and Android still referenced both, and `main` stopped compiling on those platforms.
