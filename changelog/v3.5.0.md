## v3.5.0

### iOS + Android

#### New Feature: Add 源樣明體 and 源樣黑體 Fonts

Added two new ButTaiwan font options to both platforms, filling the missing serif and sans-serif categories:

- **源樣明體 (GenYoMin)** — serif/ming typeface (16 MB)
- **源樣黑體 (GenYoGothic)** — sans-serif/gothic typeface (10 MB)

Both fonts are licensed under SIL Open Font License 1.1 by ButTaiwan.

**Changes:**
- Font picker (Tab2): 2 new font options available (total: system + 4 custom fonts)
- Copyright page (Tab1): Credits added for both new fonts with license and website links
- Font files processed with `fix_font_descender.py` to prevent descender clipping
- Keyboard extension (iOS): Loads new fonts from main app bundle via `FontRegistration`
- Settings overlay (Android): New fonts selectable from in-keyboard settings

#### Refactoring: Lexicon Core Engine

Behaviour-preserving refactor of the Lexicon / dictionary layer on both platforms, organized stage-by-stage with a Codex review pass. Public API, SQL schemas, and ranking are all unchanged; this is a structural cleanup to improve readability and to lay the groundwork for a future cross-platform shared core.

**Shared / both platforms:**
- Extracted `CandidateProcessor` from `LexiconService` — scoring, dedup, and sort live in one place instead of being inlined in the service.
- Split `LexiconService.search()` (~110 inline lines) into a ~25-line orchestrator backed by four named phases: custom-dict lookup, system-dictionary query (owns the TPS `er`↔`or` variant expansion), frequency ranking, display dedup.
- Clock injection for deterministic scoring — `sortByScore` / `calculateDecay` / `calculateUserScore` now accept a batch-level `currentTime` / `nowMs` parameter; production call sites unchanged, tests can pin time.
- Split shared models into per-type files: `DictionaryConstants`, `TaigiWord`, `InputType`, `DictionaryError`, `DictionarySource`, `ExternalLookupURLBuilder`. Mixed-concern files (`DictionaryModels`, old `DictionarySearchResult`) removed or slimmed to pure data classes.
- Deduplicated inline UPSERT SQL templates; migration functions split into one named function per version step.

**iOS (`ios/Sources/TaigiKeyboard/Lexicon/`):**
- Added file-local `bindText` helper — collapsed 47 copies of `sqlite3_bind_text(..., -1, SQLiteConnectionManager.sqliteTransient)` across three SQLite-heavy files.
- Renamed `TextProcessor.swift` → `CandidateProcessor.swift` (filename now matches type).
- `NextWordService.swift`, `CustomDictionaryRepository.swift`, `UserFrequencyRepository.swift` reorganized by concern (Constants · Types · Public API · Schema · Scoring · Pruning).

**Android (`android/app/src/main/java/com/siansiansu/taigikeyboard/ime/dictionary/`):**
- Added file-local `SQLiteStatement.bindArgs(vararg)` extension — removes manual `clearBindings()` + per-arg bind boilerplate at batch-import sites.
- `NextWordService.kt`, `CustomDictionaryService.kt`, `UserFrequencyService.kt` reorganized by concern with the same section scheme as iOS.
- `onUpgrade` migrations are now named `migrateV1ToV2` / `migrateV2ToV3` / `migrateV3ToV4` / `migrateV4ToV5` with a shared `forEachRomanRow` cursor helper.

**Documentation:**
- `docs/reports/lexicon-refactor-ios.md` and `docs/reports/lexicon-refactor-android.md` record the refactor stage-by-stage with hot-zone verification checklists.
- `docs/engine/binary-format.md` added; `nextword.md` / `trie.md` updated to match.

**Explicitly out of scope** (deferred to a later branch):
- SQLite concurrency / connection-manager collapse (deferred pending characterization tests on both platforms).
- Actual cross-platform shared-core extraction (Swift Package / KMP) — this refactor only lays the groundwork.
