## v3.5.0

### iOS + Android

#### New Feature: Add 源樣明體 and 源樣黑體 Fonts

Added two new ButTaiwan font options to both platforms, filling the missing serif and sans-serif categories:

- **源樣明體 (GenYoMin)** — serif/ming typeface (16 MB)
- **源樣黑體 (GenYoGothic)** — sans-serif/gothic typeface (10 MB)

Both fonts are licensed under SIL Open Font License 1.1 by ButTaiwan.

**Changes:**
- Font picker (Tab2): 2 new font options available (total: system + 4 custom fonts)
- Copyright page (Tab1): Credits added for both new fonts with license and website links
- Font files processed with `fix_font_descender.py` to prevent descender clipping
- Keyboard extension (iOS): Loads new fonts from main app bundle via `FontRegistration`
- Settings overlay (Android): New fonts selectable from in-keyboard settings

#### Bug Fix: Emoji Key Commits Active Preedit Atomically (Parity)

When an emoji key was pressed mid-composition, the active preedit (romanization buffer) was discarded instead of being committed. Both platforms now commit the active candidate atomically before inserting the emoji, matching the behavior of every other character key.

#### Refactoring: Lexicon Core Engine

Public API, SQL schemas, and ranking are all unchanged; this is a structural cleanup to improve readability and to lay the groundwork for a future cross-platform shared core.

- Split shared models into per-type files: `DictionaryConstants`, `TaigiWord`, `InputType`, `DictionaryError`, `DictionarySource`, `ExternalLookupURLBuilder`. Mixed-concern files (`DictionaryModels`, old `DictionarySearchResult`) removed or slimmed to pure data classes.

**iOS (`ios/Sources/TaigiKeyboard/Lexicon/`):**

#### Bug Fix: Drop Stale Autocomplete Results After Buffer Change

When backspacing to empty (or composing changing mid-search), an in-flight autocomplete `Task` could deliver results for the *prior* buffer state and overwrite the now-cleared candidate row, leaving residual candidates on screen until the next keystroke. `AutocompleteService` now captures `composing.rawInput` at function entry and re-checks `activeComposingContext()` after each `await`; if the context changed, it returns `isOutdated: true` so KeyboardKit's `AutocompleteContext.update(with:)` early-returns and leaves the cleared state intact.

#### Bug Fix: Next-Word Candidate Commits POJ Text in POJ Mode

Tapping a next-word candidate in POJ mode inserted the raw TL form (e.g. `tsiok`) while the UI correctly showed the POJ form (`chiok`). Root cause: `ActionHandler+Suggestions.parseRomanAndHanzi` preferred the dead-defensive TL sidechannel over the mode-shaped display string. The two `roman` consumers are now forked at the commit site — insertion path uses `suggestion.text` (matches UI), association path keeps the TL sidechannel. Translate-swap and TPS modes preserved via existing `effectiveSwapped` branch awareness. Android already used a single source so was unaffected.

#### Bug Fix: SF Symbol Locale Pinned to Latin

SF Symbol icons in the Dictionary tab and toolbar could render incorrectly on devices configured for non-Latin locales. The icon view now locks `locale` to `en_US` and preserves the configured tint.

#### Bug Fix: CFBundlePackageType in Info.plist

Added `CFBundlePackageType` (`APPL` for the main app, `XPC!` for the keyboard extension) to satisfy App Store Connect bundle-type validation.

### Dictionary

#### Bug Fix: Restore POJ ASCII Folding in `poj_num` / `poj_notone`

Regression introduced in the Lexicon refactor's `kesi → taigi-converter` migration: the previous pipeline applied `o͘→oo`, `ⁿ→nn`, `O͘→OO`, `ᴺ→NN` substitutions before writing `poj_num`. The new converter has no equivalent ASCII-folding entry point, so 33,966 rows (~21% of romanization queries) shipped with non-ASCII `o͘` / `ⁿ` in `poj_num` and `poj_notone`, propagating into `dictionary.trie`. Users typing POJ in ASCII (e.g. `soann` for 山, `hoo` for 予) missed those entries.

**Fix:**
- `taigi-converter` submodule bumped to add `toToneNumberAscii` export with the same substitutions as the legacy `kesi.tsuan_ascii`.
- `taigi_batch.js`, `taigi_bridge.py`, `romanization.py` route ASCII-only requests through the new entry point.
- `stages/numtone.py` now raises a regression guard if any `poj_num` row contains `o͘` / `ⁿ` / `ᴺ` after folding.
- 9 per-source CSVs regenerated; `dictionary.csv` / `.db` / `.trie` / `dictionary.bin` / `association.bin` rebuilt and redeployed to both platforms.

Spot check verified: `予 hō͘ → hoo7` (was `ho͘7`), `山 soaⁿ → soann1` (was `soaⁿ1`), `影 iáⁿ → iann2` (was `iaⁿ2`). 0 rows contain non-ASCII in `poj_num` post-fix.

#### Refactoring: Pipeline Consolidation (Steps 0–11)

Unified the per-source dictionary build pipelines under a single declarative orchestrator. Behavior-preserving — pre/post SHA256 parity verified at every step.

- `common/source_bits.py` is now the single source of truth for source bitmask positions, tier multipliers, and column ordering. Four build scripts (`01_merge_csv.py`, `05_generate_association.py`, `10_create_dictionary_bin.py`, `11_create_association_bin.py`) import from it instead of carrying local literals.
- New `pipeline/run.py` discovers `sources/<cat>/<key>/config.yaml` and runs the declared stage list per source.
- `pipeline/config_schema.py` validates each config (source name must match `SOURCE_BITS`, stage ordering invariants enforced).
- 11 stage wrappers under `common/stages/` cover cleanup, expand, frequency, poj, numtone, notone, abbrev, source, extract, select, merge, variants.
- Authored `config.yaml` for each of the 9 sources (itaigi, sitbut, taihoa, taijit, kautian, kungge, stti, taigitv, khpoo).
- `kesi` Python dependency fully migrated to `taigi-converter`; tier-based ranking bonus introduced.
