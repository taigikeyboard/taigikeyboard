## v3.6.2

Headline release: **keyboard theme picker** — a new 主題 tab to choose a keyboard look, built-in themes in three key styles (經典 filled / 框線 outlined / 簡潔 borderless) across several colours including soft gradients and a dark 暗眠山貓 (Catppuccin) theme, and a custom-theme editor for saving your own. Plus a new 顯示羅馬字 toggle for the 漢羅 literal-roman candidate, and an iOS fix that restores custom-dictionary words in the keyboard candidates.

### Shared (iOS + Android)

#### New Features

- **Keyboard theme picker.** A new 主題 tab lets you choose how the keyboard looks. Built-in themes come in three key-style families — 經典 (filled keys), 框線 (transparent keys with a 1pt outline), and 簡潔 (transparent keys, no outline) — each carrying the same colours: 預設 (adaptive, follows light/dark) plus five light-only soft gradients (櫻花 / 金煌 / 海風 / 翠青 / 藤紫) and 暗眠山貓 (Catppuccin Mocha), the first dark-only built-in theme. (#400–#428)
- **Custom theme editor.** Create and save up to 5 custom themes — set the keyboard colour roles, key sizes, and key-shadow intensity, with a live keyboard preview. (#404 / #405 / #417)
- **顯示羅馬字 (show romanization) toggle.** The 漢羅 (Han-Lo) literal-roman first candidate added in v3.6.1 is now a setting (default on). Leaving it on keeps the romanization you type as the first candidate; turning it off frees candidate-strip space (commit the romanization with Enter). Available in 拍字設定 and the in-keyboard quick settings. (#398)

#### Changes

- **The active theme now paints every keyboard surface.** The theme background / gradient paints the keyboard, candidate strip, expanded candidate overlay, and the symbol / layout / settings overlays for a continuous look; the first-candidate highlight and pressed-key feedback take a tint of the theme hue. (#415 / #420 / #422 / #429)
- **Global font moved to 齒盤設定 (keyboard settings).** The keyboard font is now a Settings-tab option, decoupled from individual themes. (#406 / #418)

### iOS

#### Bug Fixes

- **Custom-dictionary words appear in keyboard candidates again.** Imported or added custom words were not surfacing as keyboard candidates in any input mode (TL / POJ / TPS); the keyboard extension now warms the custom-dictionary connection on launch. (#399)
- **Theme rendering fixes.** The keyboard no longer freezes when opening the symbol / layout / settings overlays on a gradient theme; English-mode candidate text and the emoji-switch key glyph now follow the active theme; the expanded candidate overlay paints the theme gradient. (#420 / #429 / #430)

### Android

#### Bug Fixes

- **Foreground stays readable on light themes in dark mode.** The five light-only gradient themes keep their light look in system dark mode; key glyphs and candidate text now stay dark instead of flipping to unreadable white. (#425)

### Engine (Rust shared core)

- **顯示羅馬字 toggle wire.** `FetchAtPos.literal_roman_candidate_disabled` (field 6, inverted sentinel — proto3-default `false` = show = legacy) gates **only** the §34 literal-roman prepend in `composing::dispatch::handle_fetch_at_pos`; natural roman / OOV-synth candidates are unaffected, and commit identity stays canonical so cross-mode learning is untouched. (#398)
- Generated proto + xcframework + jniLibs regenerated via `make build`.

### Dictionary

- Regenerated via `make dict` at release; no (漢字, tl) pair changes vs v3.6.1.
