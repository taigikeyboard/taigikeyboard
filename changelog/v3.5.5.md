## v3.5.5

### iOS + Android

#### Refactoring: Phase IV-B NextWord prediction on Rust

Fourth slice of the cross-platform Rust shared core. The NextWord bigram engine — decide / record-association / filter+merge+score / boost / context-timeout / state-snapshot — moves from per-platform Swift / Kotlin into a new Rust crate (`engine/nextword/`) called from both platforms via `RustEngineBridge.nextword*`. Persistence (SQLite `user_association.db` + `association.bin` mmap) stays on the platform side until the v3.5.6 Lexicon slice. Behavior-preserving on both platforms; dogfood-verified against the v3.5.4 baseline.

**v3.5.5 — NextWord slice (#198):**
- New `engine/nextword/` crate with eight modules: `lib`, `api`, `dispatch`, `handle`, `decide`, `filter`, `scorer`, `booster`. Pure logic; SQLite / mmap I/O stays platform-side. `Engine: Send` compile-time assertion + `#![forbid(unsafe_code)]`. Singleton `EngineHandle` (`Mutex<Engine>` + `Mutex<u64>` `last_generation`) routes intents through `dispatch::handle`; envelope-mismatch resets state silently before the request processes.
- New `nextword.proto` schema — 9 oneof methods (`WordSelected` / `Backspace` / `ContextTimeoutFired` / `ClearForNewComposing` / `ResetFull` / `UpdateLastSelectedWord` (Android-only Space-path) / `SetIsShowing` / `FilterPredictions` / `BoostCandidates` / `NextWordQueryState`); 4 result variants (`DecideResult`, `FilterResult`, `BoostResult`, `StateSnapshot`); 6 effect variants (`RescheduleContextTimeout`, `CancelContextTimeout`, `RecordAssociation`, `RecordCompoundAssociations`, `QueryPredictions`, `ClearPredictionsUI`). `envelope.proto` adds `CMD_NEXTWORD = 4` + payload tag 13, plus `Platform` enum, plus `AppConfig.is_translate_swapped` / `is_association_recording_enabled` / `platform_id` fields. Generated Swift (`nextword.pb.swift`) and Java protobuf-javalite builders committed.
- Two distinct `u64` generations on the wire — `Request.generation` (envelope IME-session ID; engine resets state on mismatch) vs `state.current_generation` (per-intent monotonic, returned via `DecideResult` / re-checked on `FilterPredictions.query_generation`). `Engine::reset()` bumps `current_generation` by `wrapping_add(1)` so pre-reset in-flight `FilterPredictions` reliably surface `was_stale=true` (Codex post-impl review).
- `decide` table branches on `AppConfig.platform_id` for two known iOS / Android divergences: compound-split separator (iOS `-` only / Android `-`+whitespace) and noise-punct check (iOS first-char / Android all-chars-of-superset). All other behavior identical across platforms. Constants pinned: `ASSOCIATION_TIMEOUT_MS = 10_000`, `CONTEXT_TIMEOUT_MS = 30_000`, `LN_2 = 0.693`, scorer constants (`USER_WEIGHT = 50.0`, `DICT_WEIGHT = 1.0`, `LEARNING_BONUS = 300.0`, `DECAY_HALF_LIFE_HOURS = 168.0`, `HIGH_USAGE_DECAY_FLOOR = 0.95`, `LOW_USAGE_DECAY_FLOOR = 0.30`, `HIGH_USAGE_THRESHOLD = 3`).
- `filter` step merges raw rows by `(hanzi, tl)` via `IndexMap` (insertion order preserved — minor parity correction toward Android). Scoring summed on collision; sort desc by score; default limit 30. `Source::Unspecified` / `Platform::Unspecified` → `FailInvariant` (Codex v1 P2). Empty `hanzi` rows dropped silently. Roman-mode drops empty-TL rows; Hanji-mode keeps them.
- iOS bridge surface: new `RustEngineBridge+NextWord.swift` extension exposes 9 typed methods (`nextwordWordSelected` / `nextwordBackspace` / `nextwordContextTimeoutFired` / `nextwordClearForNewComposing` / `nextwordResetFull` / `nextwordSetIsShowing` / `nextwordFilter` / `nextwordBoostCandidates` / `nextwordQueryState`) + synth value types (`NextWordDecideResult` with sealed `Effect`, `NextWordAssociationPair`, `NextWordEnginePrediction`, `NextWordFilterResult`, `NextWordRawRow`, `NextWordStateSnapshot`). iOS intentionally omits `nextwordUpdateLastSelectedWord` (Android-only Space-path).
- Android bridge surface: new region inside `RustEngineBridge.kt` adds the same 9 methods PLUS `nextwordUpdateLastSelectedWord` (Codex v1 P1: preserves "compound-only / no timer / no gen bump" Space-path semantics). Synth Kotlin data classes mirror iOS: `NextWordDecideResult` (sealed `Effect`), `NextWordAssociationPair`, `NextWordEnginePrediction`, `NextWordFilterResult`, `NextWordRawRow`, `NextWordStateSnapshot`.
- iOS swap: `NextWordController` drops the `persistedState: NextWordPersistedState` field (engine owns state in Rust); caches `lastSelectedWord` / `isShowing` echoed from every `NextWordDecideResult`. New `envelopeGen: UInt64` + `bumpEnvelopeGeneration()` mirrors the composing-slice pattern; `KeyboardViewController.textWillChange` calls it on real input-context changes alongside the existing `manager.bumpGeneration()`. Public API preserved (`process`, `rePredictAfterBackspace`, `resetAndClearUI`, `clearDisplay`, `lastSelectedWord`, `isShowing`). `handleQueryResult` runs raw rows back through `nextwordFilter(...)`, then pushes UI visibility back to engine state via `nextwordSetIsShowing(...)`. `bumpEnvelopeGeneration()` owns the cross-field UI-clear platform-side (engine cannot, post-mismatch wipe closes the `was_showing` gate).
- iOS service: `NextWordService.predict()` returns `[RustEngineBridge.NextWordRawRow]` (un-merged un-scored rows tagged by `Source`); the bridge filter does score+merge+sort+limit. `AutocompleteService.applyContextBoost` routes through `RustEngineBridge.nextwordBoostCandidates(words: [String], …)` with a per-display-text FIFO `remapBoostedWords` helper that recovers original `TaigiWord` identity post-bridge.
- Android swap: `NextWordHandler` drops the `state: NextWordPersistedState` field; caches `lastSelectedWord` / `isShowing` echoed from every `NextWordDecideResult`. New `envelopeGen: Long` + `nextwordEnvelopeGeneration()` getter. Public API preserved (`getLastSelectedWord`, `isShowingNextWordCandidates`, `setShowingNextWord`, `resetContext`, `clearNextWordState`, `handleNextWordPrediction`, `updateLastSelectedWord`, `handleBackspaceForNextWord`). `clearNextWordState` explicitly closes the visibility gate via `SetIsShowing(false)` before `ClearForNewComposing` to avoid recursive `onClearCandidates`. Empty-backspace path bumps `envelopeGen` + `ResetFull` + forced `onClearCandidates()` to preserve the pre-Rust unconditional-clear behavior. `extractCurrentWord` companion preserved (UI-side helper used by `CandidateClickHandler`); `isNoise` / `splitCompoundWord` companions removed (only the `WordSelected` path needed them, and it now runs fully inside the Rust crate). `String.toEngineInputMode()` file-level extension converts `EngineSettings.inputMode: String` → `InputMode` enum at bridge call sites.
- Android service: `NextWordService.predict()` returns `List<RustEngineBridge.NextWordRawRow>`. Drops `NextWordPredictor` interface implementation; concrete class remains the wired binding via `CompositionRoot.nextWord`. `TaigiAutocompleteService.applyContextBoost` routes through `RustEngineBridge.nextwordBoostCandidates` with the same `remapBoostedWords` helper pattern. New `nextwordEnvelopeGeneration: Long` parameter on `autocomplete()` so the boost call shares state with `NextWordHandler` in the singleton `EngineHandle`. `SmartbarManager` exposes `getNextwordEnvelopeGeneration()` and `CandidateUpdateCoordinator` plumbs it through.
- iOS bridge access fix: three helpers in `RustEngineBridge.swift` (`nextRequestID`, `recordFailure`, `RustVec.toArray`) promoted from `private` / `fileprivate` to default `internal` so the new `RustEngineBridge+NextWord.swift` extension file can share the diagnostics ring-buffer + request-id sequence + RustVec helper.
- Engine bump-on-envelope-reset: `Engine::reset()` now bumps `current_generation` via `wrapping_add(1)` instead of zeroing the state struct. Pre-fix, an in-flight `FilterPredictions` tagged with generation `G` could collide with the post-reset state's `current_generation` if a same-cycle `ResetFull` (or any state-mutating intent) happened to land on `G` — `filter.rs` only checks equality, so the stale result would be re-rendered as fresh. Bump-on-reset closes the window. Two new unit tests in `engine/nextword/src/handle.rs` pin the regression + the `u64::MAX` wrap.
- Cross-field UI-clear ownership: `NextWordController.bumpEnvelopeGeneration()` (iOS) now also stops the context-timeout timer + force-clears the suggestion bar via `contextUpdater?.resetNextWordSuggestions()` if `cachedIsShowing` was true + nils `cachedIsShowing` / `cachedLastSelectedWord`. The engine cannot emit `ClearPredictionsUI` post-mismatch (the wipe sets `is_showing=false` before any subsequent intent processes), so the platform owns the UI-clear synchronously here. Android `resetContext()` left unchanged on purpose — per its existing doc the `SmartbarManager` caller owns the UI clear on field-switch.
- Per-platform parity test pattern: iOS `RustEngineBridgeNextWordTests` (518 LOC, 25 tests) replaces the deleted `NextWordEngineTests` / `NextWordScorerTests` / `AutocompleteContextBoosterTests` — exercises the FFI seam (proto encode → dispatcher → synth value types) under iOS-platform `AppConfig`. Cross-language tolerance 1e-7 (Codex v1 P2). Android-side parity is covered by Rust workspace tests + iOS XCTest mirror + real-device dogfood per `feedback_path_g_delete_mirrors.md` — Android JVM unit tests can't load `librust_taigi.so`, so `NextWordEngineTest`, `NextWordScorerTest`, `NextWordHandlerTest` are deleted.
- iOS deletions (770 LOC): `NextWord/{NextWordEngine,NextWordOutcome,NextWordScorer,RawNextWordPrediction,EnginePrediction,AutocompleteContextBooster}.swift` and the three companion test files.
- Android deletions (~720 LOC): `ime/core/nextword/{NextWordEngine,NextWordOutcome,NextWordScorer,RawNextWordPrediction,EnginePrediction,NextWordPredictor}.kt`, `ime/text/composing/AutocompleteContextBooster.kt`, plus the three test files. The `ime/core/nextword/` directory is removed.
- 218+ cargo workspace tests pass (174 existing + 43 new in `nextword` + 2 new in `nextword::handle`). Codex pre-impl review APPROVED v4 (4 rounds). Codex post-impl review APPROVED after 3 P2 fixes (under-fetch on `NextWordService.predict` → restored 2× over-fetch; iOS `bumpEnvelopeGeneration` had no caller → wired into `KeyboardViewController.textWillChange`; envelope-reset generation collision → bump-on-reset).
