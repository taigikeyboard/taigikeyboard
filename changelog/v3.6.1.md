## v3.6.1

Headline release: **cross-input-mode 詞庫 consistency** — user-frequency, next-word prediction, and the custom dictionary now behave the same whether you type in TL, POJ, or TPS, and homographs (重 tāng / tîng) keep independent frequency counts. Plus a privacy change (learned typing data is excluded from OS auto-backup), a default-on 姓名 appendix, literal TL / POJ composing (no spelling conversion), and several TPS / continuous-input segmentation fixes.

### Shared (iOS + Android)

#### New Features

- **Cross-input-mode user data (詞頻 / 詞關聯 / 自訂詞).** Frequency learning, next-word prediction, and custom-dictionary lookup now share results across TL / POJ / TPS — a word learned or added in one input mode is found and ranked in the others. A Taiwanese word's identity is the (漢字, canonical-TL) pair, so homographs stay distinct. (#382 / #383 / #384 / #386)
- **Per-reading frequency for homographs.** User-frequency is keyed by the (漢字, canonical-TL) pair: 重/tāng (重量) and 重/tîng (重複) now keep separate counts and rank independently instead of sharing one bucket. (#386)
- **Cross-mode custom dictionary.** A custom word added in one input family is now findable from all of TL / POJ / TPS, in both the keyboard candidate strip and the dictionary browser. Existing entries are backfilled on upgrade. (#384)

#### Bug Fixes

- **Continuous-input next-word recall + de-dup.** Next-word associations learned through continuous input now recall correctly (previously they could silently vanish), and a learned next word shows once instead of twice. (#382 / #383)
- **Literal TL / POJ composing.** The composing display now shows exactly the letters you type — no automatic spelling conversion. TL `teng2` stays `téng` (no fold to `tíng`); POJ `ting2` stays `tíng`. Frequency / association learning stays shared across modes. (#390)
- **TPS first-tone continuous input.** A first-tone TPS phrase now segments correctly both with a separating space (`ㄍㄠ ㄉㄞ`) and without one (`ㄍㄠㄉㄞ`) → 交代. (#391 / #392)
- **Whole-word continuous input honours the dictionary form.** `hoogua` now offers 予我 `hōo--guá` (the dictionary 輕聲 form) at the top instead of a space-joined `hōo guá`. Dictionary `-` / `--` / space separators are all respected. (#380)
- **Leading 輕聲 `--` is document text.** Typing a leading `--` now inserts it as normal editable text and only the following syllable underlines while composing (matches MOE). (#379)
- **First-candidate keycap hint restored.** The first candidate again renders a filled keycap-colour background (white in light theme, dark keycap shade in dark) in both the candidate strip and the expanded overlay. (#373)

#### Changes

- **Auto-space + attaching punctuation.** With auto-space on, typing attaching punctuation (`。！？，` … and closing brackets / quotes) after a committed word now moves the trailing space to after the punctuation: `guá? ` not `guá ?`. (#381)
- **姓名 (name) appendix defaults on.** The kautian 姓名附錄 subcollection now defaults to enabled, so surname candidates appear by default; an explicit off setting is preserved. (#389)

### iOS

#### Changes

- **Learned typing data excluded from iCloud / OS auto-backup.** The three user-data databases (user-frequency, word-association, custom dictionary) are now marked excluded from system backup. Reinstalling or moving to a new device no longer auto-restores them via iCloud — use the in-app 備份 (`.taigi` export / import) to carry them over. Pre-existing installs are backfilled on first launch after upgrade. (#388)

### Android

#### Changes

- **Custom-dictionary 30,000-entry cap (parity with iOS).** Adding or importing custom words now stops at 30,000 entries; existing entries past the cap are kept (never evicted), and an import that would overflow reports the skipped rows. (#385)

### Engine (Rust shared core)

- **(漢字, canonical-TL) pair-key identity** threaded through frequency, next-word association, and custom-search derivation so the three user-data axes (search / display / identity) stay orthogonal. `FrequencyEntry` gains `canonical_tl`; `FrequencyMap` becomes a nested `display → (tl → data)` map with a tolerant exact-then-legacy lookup that never sums readings. (#382 / #383 / #386)
- **Cross-mode custom-search ops** `derive_custom_search_keys` / `derive_custom_query_key` (phonetics) own all three-family ({tl, poj, tps} × {num, notone, abbrev}) key derivation — platforms never re-implement family logic. (#384)
- **Read-layer reading-variant collapse** (`nextword::filter`) folds separator / tone-only `next_tl` variants of the same (漢字, reading) so continuous + normal commits don't double-list. Separator-based, never tone-mark-based, so a genuine tone-1 reading stays distinct. (#382)
- **TPS continuous segmentation.** Space becomes a soft syllable separator stripped from the TPS shadow before lattice build (`build_separator_shadow`, #391); a phonotactic gate stops the per-keystroke adjust from folding a stop initial into an entering-tone coda when the resulting syllable is invalid (#392).
- **Literal composing.** `convert_syllable` places the tone mark directly on the typed TL / POJ syllable (`apply_tl_tone_literal` / `apply_poj_tone_literal`), validity-gated by `split_initial_final ∘ normalize_to_tl`; `canonical_tl_form(Tl)` drops only `eng→ing` / `ek→ik`. (#390)
- **Slot-0 dict-separator promotion** in `assemble_candidates` (display layer) prefers a full-span dictionary candidate's canonical roman over the walker's space-joined synthesis when they are the same reading. (#380)
- Generated proto + xcframework + jniLibs regenerated via `make build`.

#### SQLite hygiene

- Dropped the redundant `idx_user_prev_word` index (left-prefix subset of the `(prev_word, prev_tl)` composite); `PRAGMA optimize` runs once after migration; user-frequency / association record errors are structured-logged instead of silently swallowed; best-effort `VACUUM` after a user bulk-clear. No observable behavior change. (#387)

### Dictionary

- Regenerated via `make dict` at release; no (漢字, tl) pair changes vs v3.6.0 (source-flag refresh only).
