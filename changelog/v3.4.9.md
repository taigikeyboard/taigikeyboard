## v3.4.9

### iOS

#### Refactoring: Eliminate dictionary.db — Binary mmap Migration (48 MB → 12.7 MB, −73%)

Replaced SQLite `dictionary.db` with compact binary mmap files for all read-only dictionary data. SQLite retained only for user-writable databases.

**Before**: `dictionary.db` (44 MB) + `dictionary.trie` (4.1 MB) = 48.1 MB
**After**: `dictionary.trie` (4.1 MB) + `dictionary.bin` (4.4 MB) + `association.bin` (3.1 MB) + `hanzi.trie` (1.1 MB) = 12.7 MB

- **DictionaryBinaryReader**: mmap-based O(1) rowid→record lookup with offset table; 16-bit bitmask replaces 13 boolean SQL columns; `loadUnaligned` for safe unaligned integer decoding
- **AssociationBinaryReader**: mmap-based binary search on sorted key table for NextWord bigram predictions; replaces `word_association` SQLite table
- **Hanzi trie**: MARISA trie with hanzi prefix → rowid; replaces SQL `LIKE '%x%'` full table scan for dictionary exploration (Tab3)
- **Multi-trie C bridge**: Handle-based API (`trie_create`/`trie_h_lookup`/`trie_h_prefix_search`/`trie_h_close`) supporting 8 concurrent trie instances; replaces single global trie
- **TrieService multi-instance**: Refactored from singleton-only to support multiple named trie instances; `.shared` continues to manage `dictionary.trie`
- **DictionaryRepository**: Rewritten from SQLite to binary reader; `EnabledDictionaries` extracted with `sourceBitmask()` method; 3-layer bitmask filter (variant exclusion, khiin exclusion, source OR match) equivalent to previous SQL WHERE
- **NextWordService**: Dict association path migrated from SQLite to `AssociationBinaryReader`; preserves 2× over-fetch for dedup merging; `buildDictWhereCondition()` → `buildDictBitmask()`

#### New Files
- `Lexicon/Database/DictionaryBinaryReader.swift` — binary dictionary mmap reader
- `Lexicon/Database/AssociationBinaryReader.swift` — binary association mmap reader

#### Removed
- `Resources/Dictionaries/dictionary.db` — replaced by `dictionary.bin` + `association.bin`

### Build Pipeline
